# 2026-05-20 LLM Gateway 首页重设计方案（B：极客终端面板风格）

## 一、目标

将当前 LLM Gateway 首页从“普通黑白后台/基础图表页”重构为：

> 面向 AI Gateway / 中转系统运维人员的 **极客终端控制台首页**

该首页必须优先服务以下核心场景：

1. **高并发流量管控**
2. **渠道调度均衡与故障切换**
3. **API 资产安全与密钥风险预警**
4. **成本燃烧速率与配额边界监测**
5. **高频运维操作的低跳转心流**

首页不是面向运营或老板的大屏，而是面向开发者/运维工程师的：

- 高信息密度
- 强状态感知
- 快速下钻
- 极少跳页
- 暗色高对比
- 等宽数字/日志优先

---

## 二、选定方向

用户已在 brainstorming 过程中明确选择：

- **最终风格方向：B（极客终端面板风格）**

保留“运维指挥中心”的信息架构，但视觉语言改为：

- 深色终端底色
- 紧凑网格布局
- 等宽字体与日志感表达
- 语义化状态灯
- 低装饰、高扫描效率
- Drawer 侧滑下钻而非多页面跳转

1. **系统现在稳不稳**
2. **请求流量堵不堵**
3. **成本和安全危险不危险**

## 四、视觉语言（B 风格）

### 4.1 整体气质

- 深黑蓝 / 石墨蓝灰背景
- 高对比、低装饰、强层级
- 更像 Grafana / k8s / NOC 终端，而不是 BI 看板
- 主体偏“值班工程师工作台”而非“战情大屏”

### 4.2 颜色系统

#### 背景层
- 主背景：深黑蓝
- 面板背景：亮一阶的终端灰
- 边框：细发光边线

#### 状态语义色
- 绿色：健康 / 正常 / 低风险
- 黄色：高延迟 / 临界限额 / 预警
- 红色：熔断 / 大面积错误 / 高危风控事件
- 青色：实时流量 / 路由链路 / 在线状态
- 紫色：模型 / 成本 / AI 路由相关
- 灰色：停用 / 无数据 / 非活跃

### 4.3 字体系统

推荐：
- 标题：Inter / IBM Plex Sans / SF Pro
- 数字与日志：JetBrains Mono / IBM Plex Mono / Roboto Mono

规则：
- 所有关键数字（RPS/TTFF/Cost/Token）必须等宽
- 所有 request id / channel id / key / trace 字段必须等宽
- 标签简短，避免长段运营文案

### 4.4 面板风格

#### 指标卡
- 扁平硬朗
- 微弱发光边框
- 大号数字
- 小型趋势提示

#### 状态矩阵卡
- 节点感而不是营销卡
- 更像网络节点 / 服务实例视图
- 每个卡片优先展示状态，而不是装饰

#### 日志流区域
- 终端样式
- 紧凑行高
- 彩色状态文本
- hover 高亮整条链路

### 4.5 动效策略

保留：
- 告警卡轻微脉冲
- 状态灯呼吸
- Drawer 滑入
- 指标数值刷新时轻微闪变
- 请求链路逐条刷入

避免：
- 大面积漂浮球
- 过强玻璃拟态
- 装饰性粒子动画
- 高频 repaint 动画

## 五、模块详细拆解

### A. 顶部状态带（全局北极星）

建议展示：
- RPS / QPS
- TOKEN/s
- TTFF
- P95
- HEALTHY CHANNELS
- OPEN CIRCUIT COUNT
- 429 HIT COUNT
- TODAY COST
- MONTH COST
- ACTIVE TENANTS

表现形式：
- 单行紧凑终端卡
- 数字大、标签小、更新快
- 支持 5 分钟微趋势

### B. 渠道健康矩阵

每个渠道节点展示：
- channel 名称
- provider
- region / node
- current status
- latency
- error rate
- current weight
- traffic share
- 429 次数
- 最近错误摘要

表现：
- 半表格化状态节点矩阵
- 状态灯 + 固定宽度指标列

点击行为：
- 右侧 Drawer 展示：
  - 最近错误
  - 熔断历史
  - 当前配置
  - 支持模型
  - 快捷操作（降权/停用/恢复）

### C. 路由调度链路流

每条请求链路展示：
- request id
- tenant / app
- 请求模型
- 实际路由渠道
- fallback 次数
- cache hit / miss
- 最终状态
- 总耗时

表现：
- 日志流 + 链路线混合样式
- 支持实时滚动
- 支持 pause / live 切换

点击行为：
- Drawer 展示完整 trace
- 展示 model mapping / provider selection / retry / fallback 细节

### D. 限流 / 配额 / 成本控制区

拆成三个子区：

#### D1 限流命中墙
- tenant / key 名称
- 当前 RPM / TPM
- 阈值
- 429 次数
- 最近 5 分钟趋势
- 当前状态

#### D2 成本燃烧区
- 今日成本
- burn rate ($/min)
- 本月累计
- Top 模型成本排行
- Top 渠道成本占比

#### D3 配额进度墙
- Top 10 租户配额使用率
- Top 10 key 配额使用率
- 剩余额度 / 到期情况

### E. 安全风控与审计雷达

分两块：

#### E1 风险事件流
- 敏感词命中
- 高速爆破 key
- 异常来源 IP
- 越权模型请求
- 可疑 tenant/header

#### E2 安全摘要卡
- 今日拦截数
- 高风险 IP 数
- 即将过期 key 数
- guardrails 触发数
- 被封禁对象数

点击行为：
- Drawer 打开原始请求摘要、规则命中详情、近似事件、快捷处置

### F. 运维快捷动作区

操作分组：

#### 正常操作
- 刷新全部
- 打开在线测试
- 导出最近错误日志
- 查看审计导出

#### 路由治理
- 手动熔断渠道
- 恢复渠道
- 调整权重
- 切换 fallback 策略

#### 风险处置
- 封禁 key
- 限流 tenant
- 暂时关闭某模型
- 开启严格风控模式

## 六、交互与行为规范

### 6.1 刷新策略

#### 高频区：5s
- 北极星指标
- 渠道健康矩阵
- 熔断状态
- 429 命中数
- 当前告警数

#### 中频区：15s
- 成本燃烧速率
- 渠道成本占比
- Top 模型/租户排行

#### 低频区：30~60s
- 最近操作
- key 生命周期预警
- AI 运维建议

#### 手动刷新
- 顶部提供“刷新全部”
- 每个主模块支持单独刷新
- 展示最后更新时间戳

### 6.2 告警等级

#### P0 Critical
- 大面积熔断
- RPS 断崖式下降
- 成本飙升
- 大量 429 / 5xx
- 高危安全事件

#### P1 Warning
- 单渠道高延迟
- 某 key 接近限流
- 小范围异常流量

#### P2 Notice
- key 即将过期
- 某租户成本接近阈值
- 渠道恢复 / 配置变更

### 6.3 Drawer 规则

所有以下元素都支持打开 Drawer：
- 渠道节点卡
- 路由链路项
- 限流墙项目
- 风险事件项
- 成本排行项

Drawer 结构：
- 头部：对象名 + 状态 badge + id
- 摘要：关键状态与影响范围
- 明细：时间线 / 日志 / 样本 / fallback 路径
- 底部：快捷处置动作

### 6.4 安全操作规则

危险操作必须二次确认：
- 熔断渠道
- 恢复渠道
- 封禁 key
- 调整全局权重 / fallback
- 导出敏感日志

所有操作写入最近操作流，保证可追踪。

### 6.5 降级策略

每个模块三态：
- loading
- degraded
- healthy

局部接口失败不应拖垮整个首页。

## 八、实施优先级

### P0（必须优先落地）

目标：让首页从“普通后台”变成“可用的极客运维首页”

#### 范围
1. 顶部北极星状态带
2. 渠道健康矩阵（基于现有 channels 数据）
3. 图表面板重构
4. 成本 / Token / 错误率聚合显示
5. 运维快捷动作区
6. Drawer 基础版
7. B 风格视觉改造（暗色、终端感、等宽数字）

#### 特点
- 主要是前端改造
- 可用现有 API 快速落地
- 风险低、收益大

### P1（把它真正做成中转系统控制台）

#### 范围
1. 路由调度瀑布流
2. 熔断态势总览
3. 限流命中墙
4. Top risk key / tenant 聚合
5. 安全事件流
6. 渠道 / key / tenant 快捷处置动作增强

#### 特点
- 需要新增后端聚合接口
- 完成后首页将具备真正的 AI Gateway 作战属性

### P2（高级体验增强）

#### 范围
1. 拖拽布局
2. 个性化看板
3. 趋势热图 / 热力图
4. AI 运维建议增强
5. 大屏模式 / 值班模式
6. 高级联动筛选

#### 特点
- 锦上添花，不阻塞核心价值

## 九、实施建议

### 9.1 最稳妥路径

#### 第一阶段
先做首页重构，不动业务逻辑：
- 重组现有接口数据
- 统一视觉语言
- 强化状态扫描效率

#### 第二阶段
再补后端聚合接口：
- 路由链路流
- 熔断状态
- 限流热点
- 安全风险聚合

#### 第三阶段
最后把首页与现有二级页面深度联动：
- 首页看总览
- Drawer 看细节
- 二级页面做深度操作

### 9.2 与现有页面的关系

首页不替代二级页面，而是做中枢：
- 首页看渠道健康 → 进入渠道管理
- 首页看路由链路 → 进入运行时观测
- 首页看安全事件 → 进入审计与运行时 / 审计导出
- 首页看限流墙 → 进入配额管理
- 首页看成本燃烧 → 进入账单管理 / 定价管理
- 首页看记忆异常 → 进入记忆治理

## 十、最终结果目标

首页最终应从现在的：
- 黑白文字
- 普通 dashboard
- 图表堆叠
- 中转系统辨识度不足

升级为：
- 一眼看出系统健康
- 一眼看出哪个渠道出问题
- 一眼看出 fallback / 熔断 / 限流 / 成本异常
- 一跳下钻到日志与链路详情
- 高并发运维场景下可持续使用

最终定位：

> 一个真正属于 AI Gateway / 模型中转系统的极客运维首页

---

## 十一、落地建议结论

建议立即进入 **writing-plans** 阶段，输出一个按 P0/P1/P2 拆分的实施计划，并优先落地：

1. Dashboard 首页重构（P0）
2. 渠道健康矩阵（P0）
3. 成本与错误率聚合（P0）
4. Drawer 基础版（P0）
5. 路由链路流后端接口（P1）
6. 限流与安全聚合（P1）

这样可以在不推翻现有系统的前提下，最快形成显著的首页体验提升。
